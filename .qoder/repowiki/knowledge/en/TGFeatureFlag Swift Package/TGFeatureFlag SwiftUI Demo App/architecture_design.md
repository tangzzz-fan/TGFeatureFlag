Single-target iOS app built with Xcode (`TGFeatureFlagDemo.xcodeproj`). The entry point `TGFeatureFlagDemoApp.swift` defines the `DemoFeature` enum (conforming to `FeatureFlagKey`, `CaseIterable`) with string keys and per-case defaults/descriptions, then constructs a `FeatureFlagService` at launch by registering four providers in explicit precedence order: `DebugProvider` (highest), `MockRemoteProvider` (lowest/append), `UserDefaultsProvider`, and `LocalProvider`. The service is injected into the SwiftUI graph via `.featureFlagService(_)` so every view can access it through `@Environment(FeatureFlagService.self)`. `ContentView` demonstrates five scenarios — conditional tab visibility, `FeatureGate` view branching, runtime logic branching, typed configuration values, and conditional navigation — while `SettingsView` exposes a button that calls `MockRemoteProvider.fetchRemoteConfig` and then `service.triggerUpdate()` to re-render. `MockRemoteProvider` implements `FeatureFlagProvider` + `Sendable` behind a serial queue to simulate a remote config server (e.g. Firebase Remote Config).
