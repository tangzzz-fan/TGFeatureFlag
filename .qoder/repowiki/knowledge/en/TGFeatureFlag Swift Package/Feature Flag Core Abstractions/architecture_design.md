Five-file core layer exposing public protocols and a single orchestrator:
- `FeatureFlagKey.swift` declares the `FeatureFlagKey` protocol (String-backed `RawRepresentable`, `Sendable`, `Hashable`) carrying a per-flag `defaultValue: Any` and optional human-readable `description`; a default extension maps `description` to `rawValue`.
- `FeatureFlagProvider.swift` declares the pluggable value source `FeatureFlagProvider` (`name`, `value(for:) -> Any?`) so implementations can be chained.
- `AsyncFeatureFlagProvider.swift` extends `FeatureFlagProvider` with an async `fetchValues()` method for remote config providers; sync `value(for:)` returns cached values while `FeatureFlagService.refresh()` triggers the fetch.
- `FeatureFlagGroup.swift` defines `FeatureFlagGroup` (prefix + separator) and `GroupedFeatureFlag` protocol for namespacing flags; grouped flags use qualified keys (e.g., `"ui.newDesign"`) for provider lookups.
- `FeatureFlagService.swift` is the central `@MainActor @Observable` manager holding a sorted `[ProviderEntry]` list (priority + provider). Providers are registered via `register(priority:)` supporting `.highest`, `.lowest`, and `.custom(Int)`. Lookups iterate the chain returning the first non-nil cast to `T`, falling back to `feature.defaultValue as? T` before `fatalError` on mismatch. A `_updateTrigger` Int registers an Observation dependency. The service includes `FeatureFlagLogger` support via `setLogger(_:)`, fault-tolerant provider wrapping, `refresh()` for async providers, `_resolveKey(for:)` for grouped flag key resolution, and a `UserDefaults.didChangeNotification` observer.
